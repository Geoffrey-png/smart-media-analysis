> 版本：V1.0 | 编制：王淦 | 日期：2026-05-29

## 一、系统总览

系统采用 **前后端分离架构**，后端基于 Python FastAPI，前端基于 Vue 3 + Element Plus。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                             前端 (frontend/)                            │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌─────────────┐  │
│  │  api/    │ │ router/  │ │ stores/  │ │components│ │   views/     │  │
│  │ 接口封装 │ │ 路由配置 │ │ 状态管理 │ │ 公共组件 │ │  业务页面    │  │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └─────────────┘  │
└────────────────────────────────┬───────────────────────────────────────┘
                                 │ HTTP / REST API
┌────────────────────────────────┴───────────────────────────────────────┐
│                            后端 (backend/app/)                          │
│  ┌────────┐ ┌────────┐ ┌──────────┐ ┌──────────────┐ ┌─────────────┐  │
│  │  api/  │→│services│→│algorithms│ │   models/    │ │    core/    │  │
│  │ 路由层 │ │ 服务层 │ │  算法层  │ │  数据模型    │ │  配置/响应  │  │
│  └────────┘ └────────┘ └──────────┘ └──────┬───────┘ └─────────────┘  │
│                                            │                           │
│                                     ┌──────┴───────┐                   │
│                                     │    db/       │                   │
│                                     │ 数据库连接   │                   │
│                                     └──────┬───────┘                   │
│                                            │                           │
│                                   SQLite (smart_media.db)              │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、后端模块拆分

### 2.1 项目骨架

```text
backend/app/
├── main.py                   # FastAPI 应用工厂
├── api/          (路由层)     # 11 文件：接收请求，参数校验，调用 Service
├── services/     (服务层)     # 10 文件：业务逻辑编排，事务管理
├── algorithms/   (算法层)     #  2 文件：内容分析 + 推荐引擎
├── models/       (模型层)     #  7 文件：SQLAlchemy ORM 表定义
├── schemas/      (校验层)     #  6 文件：Pydantic 请求/响应模型
├── core/         (核心层)     #  2 文件：全局配置 + 统一响应
└── db/           (数据库层)   #  1 文件：引擎、会话、自动建表
```

---

### 2.2 模块详解

#### 📦 core/ — 核心配置层（2 文件）

| 模块 | 职责 |
|---|---|
| `core/config.py` | 应用全局配置：APP_NAME、API_PREFIX、数据库 URL（默认 SQLite）、上传目录 `UPLOAD_DIR`、JWT 密钥与过期时间。通过 `Settings` 类集中管理，支持环境变量覆盖。 |
| `core/response.py` | 统一 API 响应格式，提供三个工具函数：`success(data, message)` 返回 `{"code":0, ...}`、`fail(message, code)` 返回 `{"code":400, ...}`、`paginate(items, total, page, page_size)` 返回分页结构。 |

#### 📦 db/ — 数据库层（1 文件）

| 模块 | 职责 |
|---|---|
| `db/database.py` | 创建 SQLAlchemy `engine`（SQLite + `check_same_thread=False`）、`SessionLocal` 会话工厂、`Base` 声明基类。提供 `get_db()` FastAPI 依赖注入函数，在每个请求中开启/关闭数据库会话。`ensure_sqlite_schema()` 在应用启动时自动建表。 |

#### 📦 models/ — 数据模型层（7 文件，7 张表）

| 模块 | 表名 | 核心字段 |
|---|---|---|
| `models/user.py` | `users` | id, username, nickname, password_hash, role(admin/editor/auditor/viewer), age, gender, city, interests(JSON), is_active, created_at, updated_at |
| `models/content.py` | `contents` | id, title, content, summary, author, category, tags(JSON), cover_url, content_type, source_name, source_url, status(draft/pending/published/rejected/taken_down), view_count, like_count, favorite_count, comment_count, heat_score, quality_score, sentiment, publish_time, created_at, updated_at |
| `models/behavior.py` | `user_behaviors` | id, user_id(FK), content_id(FK), action_type(view/like/favorite/comment/share/dislike), duration(秒), created_at |
| `models/category.py` | `categories` | id, name, description, created_at |
| `models/tag.py` | `tags` | id, name, count(引用计数), created_at |
| `models/recommendation_log.py` | `recommendation_logs` | id, user_id(FK), content_id(FK), scene, action(exposure/click), recommend_score, reason, created_at |
| `models/operation_log.py` | `operation_logs` | id, user_id, username, role, module, action, target_type, target_id, detail(JSON), ip, created_at |

#### 📦 schemas/ — 请求校验层（6 文件）

| 模块 | 包含 Schema |
|---|---|
| `schemas/auth.py` | `LoginRequest`：用户名 + 密码 |
| `schemas/user.py` | `UserCreate`（创建用户参数）、`UserUpdate`（更新用户参数，含角色/状态/密码修改） |
| `schemas/content.py` | `ContentCreate`（新建内容，含标题/正文/分类/标签/来源等）、`ContentUpdate`（编辑内容）、`ContentAudit`（审核操作，含审核意见） |
| `schemas/behavior.py` | `BehaviorCreate`：user_id, content_id, action_type, duration |
| `schemas/recommendation.py` | `RecommendationClick`：推荐点击回传参数 |
| `schemas/news.py` | `NewsImportRequest`：新闻源 key、采集数量、全文抓取开关、自定义 RSS 地址 |

#### 📦 api/ — 路由层（11 文件，9 个路由模块 + 2 个辅助）

| 模块 | 前缀 | 核心接口 | 角色权限 |
|---|---|---|---|
| `api/deps.py` | —（依赖注入） | `require_current_user()`: JWT 解析当前用户；`require_roles(...)`: 角色鉴权装饰器；`client_ip()`: 获取客户端 IP | 所有接口共享 |
| `api/__init__.py` | — | 创建 `APIRouter(prefix="/api")`，汇聚所有子路由 | — |
| `api/auth.py` | `/api/auth` | `POST /login`: 账号密码登录返回 Token；`GET /me`: 获取当前登录用户信息 | 无需鉴权（登录）/ 需登录（me） |
| `api/users.py` | `/api/users` | `GET /`: 用户列表（分页/搜索/角色筛选/状态筛选）；`POST /`: 新增用户；`PUT /{id}`: 编辑用户；`DELETE /{id}`: 删除用户；`GET /{id}/profile`: 查看用户画像 | admin 全部；viewer 仅查看自己 |
| `api/contents.py` | `/api/contents` | `GET /`: 内容分页列表；`GET /{id}`: 内容详情；`POST /`: 新增内容；`PUT /{id}`: 编辑内容；`DELETE /{id}`: 删除内容；`POST /{id}/analyze`: 执行智能分析；`GET /audit/pending`: 待审核列表；`POST /{id}/audit`: 提交审核 | admin/editor 可写；auditor 可审核 |
| `api/behaviors.py` | `/api/behaviors` | `POST /`: 记录用户行为（触发画像更新）；`GET /`: 查询行为日志（分页/筛选） | 所有登录用户 |
| `api/recommendations.py` | `/api/recommendations` | `GET /hot`: 热门推荐；`GET /user/{user_id}`: 个性化推荐；`GET /mixed/{user_id}`: 混合推荐；`POST /click`: 推荐点击回传；`GET /analytics/summary`: 推荐效果分析 | 所有登录用户 |
| `api/dashboard.py` | `/api/dashboard` | `GET /summary`: 首页看板统计数据（用户数/内容数/今日数据/7日趋势/热门分类） | 所有登录用户 |
| `api/admin.py` | `/api/admin` | `GET /summary`: 管理员后台总览（角色分布/状态分布/来源统计/累计数据）；`GET /logs`: 操作审计日志列表 | admin |
| `api/meta.py` | `/api/meta` | `GET /categories`: 分类列表（含热度统计）；`GET /tags`: 标签列表 | 所有登录用户 |
| `api/news.py` | `/api/news` | `GET /sources`: 内置 RSS 新闻源列表；`POST /import`: 从 RSS 源采集新闻入库 | admin / editor |
| `api/uploads.py` | `/api/uploads` | `POST /`: 上传文件（图片/视频，最大 50MB），存储在 `backend/uploads/` | admin / editor |

#### 📦 services/ — 业务逻辑层（10 文件）

| 模块 | 职责 | 关键函数 |
|---|---|---|
| `services/auth_service.py` | JWT Token 生成与解析，用户登录验证逻辑 | `create_access_token()`, `login()`, `get_current_user()` |
| `services/user_service.py` | 用户 CRUD、分页查询、密码修改、画像构建、兴趣权重刷新 | `build_user_profile()`, `ACTION_WEIGHTS`（行为→权重映射）, `VALID_ROLES` |
| `services/content_service.py` | 内容 CRUD、分页搜索、标签/分类聚合、审核状态管理，调用 `content_analyzer` 进行分析评分 | `create_content()`, `analyze_content()`, `audit_content()` |
| `services/behavior_service.py` | 行为记录并触发连锁更新：更新内容互动计数 → 更新用户画像 → 刷新热度/质量评分 | `create_behavior()`, `refresh_user_profile()` |
| `services/recommendation_log_service.py` | 推荐曝光/点击记录、点击回传、推荐效果聚合分析（CTR、场景分布） | `log_recommendations()`, `log_recommendation_click()`, `recommendation_analytics()` |
| `services/dashboard_service.py` | 看板统计：用户/内容/行为/推荐总计数、今日数据、7日趋势、热门分类/标签排行 | `get_summary()` |
| `services/admin_service.py` | 管理员后台统计：角色分布、账号状态分布、内容状态分布、来源分布、累计指标 | `admin_summary()` |
| `services/operation_log_service.py` | 操作审计日志记录（记录后台关键操作）与查询（分页、时间筛选） | `log_operation()`, `list_operation_logs()` |
| `services/news_crawler_service.py` | RSS 新闻采集：内置 10+ 默认源（科技/财经/体育/娱乐/社会），支持自定义 RSS URL，解析后调用 `content_analyzer` 入库 | `get_news_sources()`, `import_news()` |
| `services/security_service.py` | bcrypt 密码哈希与验证，兼容明文 demo 账号数据的平滑升级 | `hash_password()`, `verify_password()` |

#### 📦 algorithms/ — 算法层（2 文件）

| 模块 | 职责 | 关键函数 |
|---|---|---|
| `algorithms/content_analyzer.py` | 内容智能分析：jieba 中文分词、TF-IDF 关键词提取、`CATEGORY_KEYWORDS` 规则分类（科技/财经/体育/娱乐/社会）、正负词典情感分析、热度分 `calculate_heat_score()`（浏览 0.4 + 点赞 2 + 收藏 3 + 评论 2.5）、质量分 `calculate_quality_score()`（标题/正文长度、摘要、标签、封面、互动数据） | `extract_keywords()`, `classify_content()`, `analyze_sentiment()`, `calculate_heat_score()`, `calculate_quality_score()` |
| `algorithms/recommender.py` | 推荐引擎：`normalize()` 归一化、`freshness_score()` 时间衰减。三种策略：① **热门推荐**（高分内容 + 近7日）；② **内容推荐**（标签匹配 + 用户兴趣画像加权）；③ **协同推荐**（相似行为用户偏好交集）。混合策略 `recommend_mixed()` 按比例组合，最终排序公式为 `标签匹配 x 0.45 + 热度 x 0.25 + 质量 x 0.20 + 新鲜度 x 0.10`，已浏览/不感兴趣内容自动过滤。 | `recommend_hot()`, `recommend_for_user()`, `recommend_similar_items()`, `recommend_mixed()` |

## 四、数据流与调用链路

### 4.1 后端请求处理流程

```text
HTTP Request
    │
    ▼
┌──────────────────────────────────────────────┐
│  api/ (路由层)                                │
│  - deps.py: JWT 认证 / 角色鉴权               │
│  - schemas/*.py: Pydantic 参数校验            │
│  - 调用对应 service                           │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│  services/ (业务逻辑层)                        │
│  - 编排业务流程                                │
│  - 调用 algorithms/ 获取分析/推荐结果          │
│  - 调用 db/database.py 的 get_db() 管理事务   │
│  - 调用 operation_log_service 记录审计日志     │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│  algorithms/ + models/                        │
│  - algorithms/: 算法计算（纯函数，无副作用）    │
│  - models/: ORM 查询与持久化                   │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│  core/response.py                             │
│  - 统一封装 JSON 响应返回客户端                │
└──────────────────────────────────────────────┘
```

### 4.2 关键业务链路

**用户行为 → 画像更新 → 推荐闭环：**

```text
POST /api/behaviors  (用户点赞/浏览/收藏)
        │
        ▼
services/behavior_service.create_behavior()
        │
        ├──▶ models/behavior.py: 写入 user_behaviors 表
        ├──▶ models/content.py: 更新内容的 like_count / view_count
        ├──▶ services/user_service.build_user_profile()
        │       └──▶ 读取用户所有行为 → 聚合标签权重 → 更新 users.interests(JSON)
        └──▶ algorithms/content_analyzer.calculate_heat_score()
                └──▶ 更新 contents.heat_score（热度随时间动态变化）
```

        │
        ▼

        │

## 五、模块依赖关系

```text
                      ┌─────────────────────┐
                      │     api/ (路由层)     │
                      │  10 个业务路由模块    │
                      └──────┬──────┬───────┘
                             │      │
              ┌──────────────┘      └──────────────┐
              ▼                                     ▼
    ┌──────────────────┐                  ┌──────────────────┐
    │  services/ (服务层)│                  │  schemas/ (校验层)│
    │  10 个服务模块     │                  │  6 个 Pydantic   │
    └────┬──────┬───────┘                  │  数据模型        │
         │      │                          └──────────────────┘
    ┌────┘      └────┐
    ▼                ▼
┌────────────┐ ┌────────────┐
│algorithms/ │ │  models/   │
│(无副作用的  │ │(ORM 模型)  │
│ 纯函数)    │ │            │
└────────────┘ └─────┬──────┘
                     │
              ┌──────┴──────┐
              │   core/     │
              │  config.py  │
              │ response.py │
              └──────┬──────┘
                     │
              ┌──────┴──────┐
              │    db/      │
              │ database.py │
              └──────┬──────┘
                     │
              SQLite Database
```

**依赖原则：**

- `api/` → `services/` + `schemas/`：路由层依赖服务层和校验层
- `services/` → `models/` + `algorithms/` + `core/`：服务层依赖模型层、算法层和核心层
- `algorithms/` → 仅依赖 Python 标准库 + jieba + scikit-learn（不依赖 services/models）
- `models/` → `db/`：模型层依赖数据库引擎
- `schemas/` → 独立层，仅被 api/ 引用
- `core/` → 被所有层引用（全局配置和响应格式）

## 六、扩展点

| 扩展方向 | 改造目标 | 涉及模块 |
|---|---|---|
| 替换数据库 | SQLite → MySQL/PostgreSQL | 修改 `core/config.py` 中的 DATABASE_URL 即可，models/ 无需改动 |
| 接入大模型 | NLP 分析能力升级 | 在 `algorithms/content_analyzer.py` 新增函数，services/content_service.py 切换调用 |
| 深度学习推荐 | 协同过滤 → 深度学习/Embedding | 在 `algorithms/recommender.py` 新增策略函数，保持接口签名一致 |
| 实时行为处理 | 行为入库异步化 | 新增消息队列（Kafka）消费模块，`api/behaviors.py` 改为生产者 |
| 搜索引擎 | 关键词搜索 → 全文检索 | 新增 Elasticsearch 连接模块，替换 `services/content_service.py` 中的搜索逻辑 |
| A/B 测试 | 推荐策略对比实验 | 新增 `services/ab_test_service.py`，在 `algorithms/recommender.py` 中按实验分流 |
| 多租户 | 组织隔离 | 所有 models/ 新增 tenant_id 字段，services/ 增加租户过滤逻辑 |
