## 一、内容智能分析引擎

**文件位置**: `backend/app/algorithms/content_analyzer.py`  
**调用入口**: `services/content_service.py` → `analyze_content_payload()`

### 1.1 架构设计

分析引擎采用"词典规则 + 轻量 NLP"的混合策略，所有分析能力封装为纯函数（无副作用，不访问数据库），便于单元测试和后续升级为 LLM 接口。

```text
输入: 标题 + 正文 + content_obj
          │
          ▼
  ┌───────────────────────────┐
  │   analyze_content_payload  │  ← 编排函数
  └───────────┬───────────────┘
              │
   ┌──────────┼──────────┬──────────┬────────────┐
   ▼          ▼          ▼          ▼            ▼
extract    generate   classify   analyze      detect
keywords   summary    content    sentiment    sensitive
                        │
                        ▼
              ┌─────────────────┐
              │ calculate_quality │
              │ calculate_heat   │
              └─────────────────┘
```

### 1.2 关键词提取 `extract_keywords()`

```
输入: title (str), content (str), top_k (int=8)
输出: list[str]  Top-K 关键词
```

**两级策略:**

| 条件 | 方法 | 说明 |
|------|------|------|
| jieba 可用 | `jieba.analyse.extract_tags(text, topK=top_k)` | 基于 TF-IDF 的关键词提取 |
| jieba 不可用 | 词频统计 + 内置停用词过滤 | 纯 Python 后备方案，正则匹配中英文 |

**停用词表:** `{"一个", "我们", "他们", "以及", "通过", "进行", "已经", "同时", "相关", "记者", "表示", "the", "and", "for", "with"}`

### 1.3 自动摘要 `generate_summary()`

```
输入: content (str), max_length (int=160)
输出: str  摘要文本（≤160字）
```

**算法流程:**

1. 用 `[。！？!?]` 分句
2. 提取全文 Top-10 关键词
3. 每句打分 = 包含关键词数 + 句首加权（前3句各+0.6/0.4/0.2）
4. 选分最高的3句，按原文顺序拼接
5. 超过 max_length 截断并追加 `...`

**关键参数:**

| 参数 | 值 | 说明 |
|------|-----|------|
| max_length | 160 | 摘要最大字符数 |
| 候选句数 | 3 | 最终摘要选取的句子数 |
| 句首加权 | `max(0, 3 - index) * 0.2` | 前3句的线性位置加权 |

### 1.4 内容分类 `classify_content()`

```
输入: title (str), content (str), keywords (list[str] | None)
输出: str  分类名（科技/财经/体育/娱乐/社会/文化/国际/健康/综合）
```

**算法:** 词典关键词匹配。对每个分类遍历其关键词集合，统计在文本中的命中次数，选最高分分类。

**分类词典规模:**

| 分类 | 关键词数 | 示例关键词 |
|------|---------|-----------|
| 科技 | 16 | 人工智能, AI, 算法, 机器学习, 芯片, 互联网, 大模型, 云计算 |
| 财经 | 16 | 股票, 市场, 企业, 投资, 经济, 金融, 银行, 基金 |
| 体育 | 14 | 比赛, 球星, 冠军, 联赛, 足球, 篮球, 赛事 |
| 娱乐 | 11 | 电影, 音乐, 明星, 综艺, 票房, 演唱会 |
| 社会 | 12 | 城市, 民生, 教育, 医疗, 交通, 就业, 养老 |
| 文化 | 10 | 文化, 旅游, 非遗, 博物馆, 展览, 艺术 |
| 国际 | 10 | 国际, 全球, 外交, 海外, 贸易, 联合国 |
| 健康 | 10 | 健康, 医疗, 医院, 疾病, 营养, 心理 |

> 总词库: ~99 个关键词，覆盖 8 个大类。匹配无命中时，兜底分类为"综合"。

### 1.5 情感分析 `analyze_sentiment()`

```
输入: content (str)
输出: str  "positive" | "neutral" | "negative"
```

**算法:** 正负面词典词频统计。统计正面词和负面词在文本中命中次数，差值 ≥ 2 判定为 positive/negative，否则 neutral。

**词典规模:**

| 词典 | 词数 | 示例词 |
|------|------|--------|
| 正面词 | 16 | 增长, 提升, 突破, 创新, 成功, 领先, 利好 |
| 负面词 | 16 | 下降, 风险, 冲突, 失败, 违规, 事故, 投诉, 压力 |

**判定阈值:**

```
positive - negative >= 2 → "positive"
negative - positive >= 2 → "negative"
|positive - negative| < 2 → "neutral"
```

### 1.6 敏感词检测 `detect_sensitive_words()`

```
输入: title (str), content (str)
输出: list[str]  命中的敏感词列表（排序）
```

**敏感词库:** `{"暴力", "诈骗", "谣言", "赌博", "违法", "涉黄", "恐怖", "极端"}` (共 8 词)

**触发行为:** 检测到敏感词时，`_apply_analysis()` 会自动将已发布内容状态改为 `pending`（待审核）。

### 1.7 热度评分 `calculate_heat_score()`

```
输入: view_count, like_count, favorite_count, comment_count
输出: float (0-∞)
```

**公式:**

```
heat_score = view_count × 0.4 + like_count × 2 + favorite_count × 3 + comment_count × 2.5
```

**权重设计分析:**

| 行为 | 权重 | 设计意图 |
|------|------|----------|
| 浏览 | 0.4 | 基础权重最低，反映曝光量 |
| 点赞 | 2.0 | 中度认可，约等于 5 次浏览 |
| 评论 | 2.5 | 深度参与，约等于 6.25 次浏览 |
| 收藏 | 3.0 | 最高价值，表明用户留存意愿 |

### 1.8 质量评分 `calculate_quality_score()`

```
输入: content_obj (SQLAlchemy 对象)
输出: float (0-100)
```

**评分维度与权重:**

| 维度 | 满分 | 计分规则 |
|------|------|----------|
| 标题长度 | 15 | 8-80字 → 15分，否则 → 8分 |
| 正文长度 | 30 | `min(len(content)/800 × 30, 30)` —— 800字满分 |
| 摘要质量 | 15 | ≥40字 → 15分，>0字 → 6分，无 → 0分 |
| 标签标注 | 15 | 有标签 → 15分，无 → 0分 |
| 封面图 | 10 | 有封面 → 10分，无 → 0分 |
| 互动加分 | 15 | `min(log(1 + view + like×3 + fav×4 + comment×4) × 3, 15)` |

**关键特性:**
- 互动加分使用对数函数 `log1p`，避免头部内容分数过高
- 分数硬上限 100，带 `.round(2)` 两位小数

### 1.9 编排函数 `analyze_content_payload()`

```python
def analyze_content_payload(title: str, content: str, content_obj=None) -> dict:
    """一次性执行全部分析步骤，返回完整分析结果字典。"""
```

**返回值结构:**

```json
{
    "keywords": ["人工智能", "算法", ...],
    "summary": "摘要文本...",
    "category": "科技",

    "sensitive_words": [],

}
```

## 二、推荐系统引擎

**文件位置**: `backend/app/algorithms/recommender.py`  
**调用入口**: `api/recommendations.py`

### 2.1 架构设计

推荐引擎实现三种独立策略 + 混合策略的上层调度。

```text
          ┌───────────────────────────────┐
          │      recommend_mixed()        │  ← 混合调度
          └─────────────┬─────────────────┘
                        │
      ┌─────────────────┼─────────────────┐
      ▼                 ▼                  ▼
┌─────────────┐ ┌──────────────┐ ┌───────────────────┐
│recommend_hot│ │recommend_for │ │recommend_similar  │
│  热门推荐    │ │  _user       │ │  _content         │
│             │ │ 个性化推荐    │ │  相似内容推荐      │
└─────────────┘ └──────────────┘ └───────────────────┘
```

### 2.2 通用工具函数

#### `normalize(value, max_value=100)` — 归一化

```
normalize(value) = clamp(value / max_value, 0, 1)
```
将原始分数映射到 [0, 1] 区间，用于多维度分数的统一加权。

#### `freshness_score(publish_time)` — 时效性衰减

```
| 发布时间距今 | 分数 |
|------------|------|
| ≤ 1 天     | 1.00 |
| ≤ 7 天     | 0.82 |
| ≤ 30 天    | 0.55 |
| > 30 天    | 0.22 |
```

> 时间衰减采用阶梯函数而非连续衰减，保证近期内容有显著优势。无发布时间兜底 0.3。

#### `tag_match_score(user_tags, content_tags, category)` — 标签匹配度

```
matched = Σ max(user_tags[tag], 0)  for tag in content_tags
         + max(user_tags[category], 0) × 0.7   （分类加权）
score = clamp(matched / positive_sum, 0, 1)
```

**注意:** 仅计入正面兴趣（weight > 0），负向标签在推荐层通过 penalty 机制处理。

#### `diversify(items, limit)` — 分类多样性控制

- 每个分类上限: `max(2, limit // 3)` → 10 条时上限为 3
- 先按限制挑选，剩余名额按原始排序补充
- 确保推荐结果不全部来自同一分类

### 2.3 热门推荐 `recommend_hot()`

```
推荐策略: 按 heat_score 降序取已发布内容 Top-N
候选范围: 全部 status="published" 的内容
排序依据: heat_score DESC → view_count DESC → publish_time DESC
推荐理由: "近期热度较高"
```

**评分:** `recommend_score = normalize(heat_score, 500) × 100`

### 2.4 个性化推荐 `recommend_for_user()`

**核心流程:**

```text
用户 ID
  │
  ├─→ build_user_profile()  → user_tags (画像标签+权重)
  ├─→ build_tag_weights_from_behaviors() → behavior_tags, viewed_ids, negative_tags
  │      └─ 合并: user_tags[key] += behavior_tags[key]
  │
  ├─→ 获取候选: 已发布内容 Top 500 (按 publish_time + id 排序)
  │
  └─→ 逐条评分:
         ┌────────────────────────────────────────┐
         │ t_score = tag_match_score(user_tags, tags, category)  │
         │ h_score = normalize(heat_score, max_heat)            │
         │ q_score = normalize(quality_score, 100)              │
         │ f_score = freshness_score(publish_time)              │
         │                                                      │
         │ penalty = 0.45 if 任一标签∈negative_tags else 1     │
         │                                                      │
         │ score = (t_score×0.52 + h_score×0.18                 │
         │        + q_score×0.18 + f_score×0.12) × penalty     │
         └────────────────────────────────────────┘
```

**排序权重:**

| 因子 | 权重 | 说明 |
|------|------|------|
| 标签匹配 (t_score) | 0.52 | 核心因子，基于用户画像 |
| 热度 (h_score) | 0.18 | 保证推荐内容有热度支撑 |
| 质量 (q_score) | 0.18 | 过滤低质量内容 |
| 时效性 (f_score) | 0.12 | 保证内容新鲜度 |
| 负反馈惩罚 | ×0.45 | 任何标签命中不感兴趣时整体降权 |

**筛选规则:**

1. 排除已浏览内容 (`viewed_ids`)
2. 负向标签内容整体降权 55%
3. 评分后将推荐列表通过 `diversify()` 做分类多样性控制
4. 最终结果不足 limit 时，用热门推荐补充

**推荐理由生成:**

| 条件 | 推荐理由 |
|------|----------|
| 有匹配标签 | `"因为你最近关注「{匹配标签}」"` |
| 热度 > 0.6 | `"近期热度较高"` |
| 质量 > 0.7 | `"内容质量评分较高"` |
| 无匹配 | `"为你探索新的内容方向"` |

### 2.5 相似内容推荐 `recommend_similar_content()`

```
基于单条内容查找相似内容:

score = (tag_jaccard × 0.6) + (category_match × 0.3) + (text_jaccard × 0.1)

其中:
  tag_jaccard = |target_tags ∩ content_tags| / |target_tags ∪ content_tags|
  category_match = 0.3 if content.category == target.category else 0
  text_jaccard = |target_keywords ∩ content_keywords| / |target_keywords|
```

**特点:** 仅返回 score > 0 的内容；同时比较标签交集（Jaccard）+ 分类匹配 + 关键词交集。

### 2.6 混合推荐 `recommend_mixed()`

```
if 有用户 ID:
    先尝试 personalized → 结果 ≥ limit 则直接返回
    不足时，排除已推荐+已浏览内容，用热门推荐补充
else:
    返回热门推荐
```

### 2.7 推荐基础设施

**偏好构建函数 `build_tag_weights_from_behaviors()`:**

- 遍历用户全部行为记录（JOIN Content 表获取标签）
- 按 `ACTION_WEIGHTS` 加权累加标签权重
- 浏览行为额外加分：`min(duration / 120, 2)`（观看 4 分钟满分 2 分）
- 分类标签额外乘 0.6 系数
- 同时收集 `viewed_ids`（已浏览内容 ID 集合）和 `negative_tags`（不感兴趣标签集合）

## 三、用户画像引擎

**文件位置:** `backend/app/services/user_service.py`  
**调用入口:** `api/users.py` → `GET /{id}/profile`

### 3.1 行为权重体系

```python
ACTION_WEIGHTS = {
    "view": 1,        # 浏览：基础权重
    "like": 5,        # 点赞：强兴趣信号
    "favorite": 6,    # 收藏：最强兴趣信号
    "comment": 4,     # 评论：深度互动
    "share": 4,       # 分享：传播意愿
    "dislike": -6,    # 不感兴趣：强烈负反馈
}
```

**浏览时长加成:** `min(duration / 120, 2)` —— 阅读超过 4 分钟 → 额外 +2 分。

### 3.2 画像计算流程 `calculate_user_profile()`

```text
┌─────────────────────────────────────────────┐
│  1. 查询用户全部行为 (JOIN Content)          │
│     ↓                                       │
│  2. 逐行为计算标签权重:                      │
│     tag_weights[tag] += ACTION_WEIGHTS[action]│
│     + 浏览时长加成                           │
│     ↓                                       │
│  3. 分类加权:                                │
│     tag_weights[category] += weight × 0.6   │
│     ↓                                       │
│  4. 合并用户初始兴趣:                        │
│     tag_weights[user_interest] += 2          │
│     ↓                                       │
│  5. 构建画像:                                │
│     - 正面兴趣标签（weight > 0）              │
│     - 负向兴趣标签（weight < 0）              │
│     - 分类偏好分布                            │
│     - 行为类型统计                            │
│     - 最近 10 条互动内容                      │
│     - 活跃分                                 │
└─────────────────────────────────────────────┘
```

**活跃分计算:** `active_score = Σ max(action_weight + duration_boost, 0)` —— 仅计入正面行为。

### 3.3 画像持久化 `refresh_user_profile_from_behaviors()`

每次行为记录后自动触发，更新 `users` 表的三个字段：

| 字段 | 内容 |
|------|------|
| `interests` | Top-12 正面兴趣标签（逗号拼接） |
| `profile_vector` | 完整画像 JSON（含 Top-30 正面标签、Top-20 负面标签、分类分布、行为统计） |
| `active_score` | 活跃分数 |
| `last_active_at` | 最近活跃时间 |

### 3.4 冷启动处理

```python
# 用户初始兴趣标签 → 权重 +2（弱正面信号）
for interest in split_tags(user.interests):
    tag_weights[interest] += 2

# 无行为数据时，回退到 profile_vector 中存储的历史画像
if stored and not profile["interest_tags"]:
    profile["interest_tags"] = stored.get("interest_tags", [])
```

## 四、行为记录与联动更新

**文件位置:** `backend/app/services/behavior_service.py`  
**调用入口:** `POST /api/behaviors`

### 4.1 完整调用链

```text
POST /api/behaviors  { user_id, content_id, action_type, duration }
        │
        ▼
┌───────────────────────────────────────────────────────┐
│ create_behavior(db, payload)                          │
│                                                        │
│  1. 校验: action_type ∈ VALID_ACTIONS (6种)           │
│  2. 校验: user_id 与 content_id 存在                   │
│  3. 写入 user_behaviors 表                             │
│  4. _update_content_stats(content, action)             │
│     ├─ 更新 content.view_count / like_count / ...      │
│     ├─ 重新计算 content.heat_score                     │
│     └─ 重新计算 content.quality_score                  │
│  5. refresh_user_profile_from_behaviors(user_id)      │
│     ├─ 重新聚合标签权重                                 │
│     ├─ 更新 user.interests (Top-12 标签)               │
│     ├─ 更新 user.profile_vector (完整画像 JSON)         │
│     ├─ 更新 user.active_score                          │
│     └─ 更新 user.last_active_at                        │
│  6. db.commit()                                       │
└───────────────────────────────────────────────────────┘
```

### 4.2 联动影响矩阵

| 用户行为 | 内容表更新 | 用户表更新 | 推荐影响 |
|----------|-----------|-----------|----------|
| view | view_count +1 | 画像更新, active_score更新 | 该内容入 viewed_ids，不再推荐 |
| like | like_count +1 | 标签权重 +5, 画像更新 | 相关标签推荐分↑ |
| favorite | favorite_count +1 | 标签权重 +6, 画像更新 | 相关标签推荐分↑↑ |
| comment | comment_count +1 | 标签权重 +4, 画像更新 | 相关标签推荐分↑ |
| share | — | 标签权重 +4, 画像更新 | 相关标签推荐分↑ |
| dislike | — | 标签权重 -6, 入 negative_tags | 相关标签推荐 ×0.45 penalty |

### 4.3 热度/质量实时刷新

每次行为记录后，内容的热度和质量分实时重算：

```python
def _update_content_stats(content, action_type):
    # 1. 更新互动计数
    content.view_count += 1  # or like_count, favorite_count, comment_count

    # 2. 重算热度分
    content.heat_score = calculate_heat_score(
        content.view_count, content.like_count,
        content.favorite_count, content.comment_count
    )

    # 3. 重算质量分（互动数据作为质量维度之一）
    content.quality_score = calculate_quality_score(content)
```

```text

        │

│  2. 获取 RSS XML:                                     │
│     - requests.get(url, timeout=15)                   │
│     - 403/404 → 不处理，继续下一条                     │
│     ↓                                                 │
│  3. 解析 RSS:                                         │
│     - xmltodict 解析 XML                              │
│     - 提取 title, summary, link, published            │
│     ↓                                                 │
│  4. 内容入库:                                         │
│     - 按 source_url 或 title 去重（已存在则跳过）      │
│     - 调用 content_analyzer 执行自动分析               │
│     - status = "draft"（等待人工处理）                 │
│     ↓                                                 │
│  5. 记录审计日志:                                     │
│     - module="news", action="import"                  │
│     - detail={source_key, imported, skipped}          │
└──────────────────────────────────────────────────────┘
```

### 5.2 内置新闻源

默认内置 10+ RSS 源，覆盖多领域：

| 领域 | 示例源 |
|------|--------|
| 科技 | 36氪、虎嗅、IT之家 |
| 财经 | 华尔街见闻、财联社 |
| 体育 | 虎扑体育、新浪体育 |

每个源配置包含：key, name, url, category。

### 5.3 容错设计

| 异常情况 | 处理策略 |
|----------|----------|
| RSS URL 不可达 | 捕获异常，跳过，不影响其他源 |
| XML 解析失败 | 捕获异常，跳过该条目 |
| 数据库写入冲突 | SQLAlchemy IntegrityError → 回滚，跳过该条 |
| 全文抓取失败 | 不阻塞，仅使用摘要 |

## 六、内容审核流程

**文件位置:** `backend/app/services/content_service.py` → `audit_content()`  
**调用入口:** `POST /api/contents/{id}/audit`

### 6.1 状态机

```text
                    ┌──────────┐
            ┌──────→│  draft   │←──────┐
            │       │  草稿    │       │
            │       └────┬─────┘       │
            │            │ 提交/含敏感词│
            │            ▼             │
            │       ┌──────────┐       │
            │       │ pending  │       │
            │       │ 待审核   │       │
            │       └────┬─────┘       │
            │      ┌─────┼─────┐       │
            │      ▼     │     ▼       │
            │  ┌───────┐ │ ┌────────┐  │
            │  │published│ │rejected│   │
            │  │ 已发布  │ │ 已拒绝 │───┘（可重新编辑→draft）
            │  └───┬───┘ └────────┘
            │      │
            │      ▼
            │  ┌────────┐
            └──│offline │
               │ 已下架 │
               └────────┘
```

### 6.2 审核触发条件

| 触发方式 | 条件 | 新状态 |
|----------|------|--------|
| 手动提交 | 编辑/管理员新增或编辑后提交 | `pending` |
| 自动触发 | `_apply_analysis()` 检测到敏感词 | `pending`（即使原本是 published） |
| 管理员审核 | 调用 `audit_content(status="published")` | `published` |
| 管理员拒绝 | 调用 `audit_content(status="rejected")` | `rejected` |
| 管理员下架 | 调用 `audit_content(status="offline")` | `offline` |

### 6.3 审核接口

```python
def audit_content(db, content_id, status, audit_comment, auditor):
    """
    status: "published" | "rejected" | "offline"
    audit_comment: 审核意见（拒绝时必填建议）
    auditor: 审核人用户名
    """
```

**权限控制:** 路由层通过 `require_roles("admin", "auditor")` 限制——管理员和审核员可操作，编辑不可审核。

### 6.4 与内容分析联动

```python
def _apply_analysis(content, force_category=False):
    # ... 执行分析 ...

    # 自动审核触发：检测到敏感词且状态为已发布 → 强制改为待审核
    if analysis["sensitive_words"] and content.status == "published":
        content.status = "pending"
```

这意味着发布后内容如果被重新分析并发现敏感词，会自动退回待审核状态，确保平台内容安全。
