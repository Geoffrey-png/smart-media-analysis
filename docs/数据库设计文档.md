## 二、表结构详细说明

### 2.1 users — 用户表

存储系统用户账户信息、角色权限和由行为驱动的动态画像数据。

#### 字段定义

| # | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | `id` | INTEGER | PK, INDEX | AUTO | 用户唯一标识 |
| 2 | `username` | VARCHAR(80) | NOT NULL, UNIQUE, INDEX | — | 登录用户名 |
| 3 | `nickname` | VARCHAR(80) | — | `""` | 显示昵称 |
| 4 | `password_hash` | VARCHAR(255) | — | `""` | bcrypt 哈希密码（兼容明文 demo） |
| 5 | `role` | VARCHAR(30) | INDEX | `"viewer"` | admin / editor / auditor / viewer |
| 6 | `status` | VARCHAR(30) | INDEX | `"active"` | active / disabled |
| 7 | `age` | INTEGER | — | `0` | 年龄 |
| 8 | `gender` | VARCHAR(20) | — | `"unknown"` | 性别 |
| 9 | `city` | VARCHAR(80) | — | `""` | 所在城市 |
| 10 | `interests` | TEXT | — | `""` | Top-12 兴趣标签，逗号分隔 |
| 11 | `profile_vector` | TEXT | — | `""` | 完整画像 JSON（Top-30 正面 + Top-20 负面 + 分类分布 + 行为统计） |
| 12 | `active_score` | FLOAT | — | `0` | 活跃分数（行为权重累加） |
| 13 | `last_active_at` | DATETIME | NULLABLE | — | 最近活跃时间 |
| 14 | `created_at` | DATETIME | — | `utcnow` | 创建时间 |
| 15 | `updated_at` | DATETIME | — | `utcnow` | 更新时间（自动刷新） |

#### 索引

| 索引 | 字段 | 用途 |
|------|------|------|
| PRIMARY | id | 主键 |
| UNIQUE | username | 登录名唯一性约束 |

存储系统中的全部媒体内容资产，包括手动创建、RSS 采集和上传的内容。

#### 字段定义

| # | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | `id` | INTEGER | PK, INDEX | AUTO | 内容唯一标识 |
| 2 | `title` | VARCHAR(255) | NOT NULL, INDEX | — | 内容标题 |
| 3 | `summary` | TEXT | — | `""` | 自动生成或手动填写的摘要 |
| 4 | `content` | TEXT | NOT NULL | — | 正文内容 |
| 5 | `author` | VARCHAR(100) | — | `"系统编辑"` | 作者 |
| 6 | `category` | VARCHAR(50) | INDEX | `"未分类"` | 科技/财经/体育/娱乐/社会/文化/国际/健康/综合 |
| 7 | `tags` | TEXT | — | `""` | 逗号分隔标签 |
| 8 | `cover_url` | VARCHAR(500) | — | `""` | 封面图 URL 或上传路径 |
| 9 | `source_name` | VARCHAR(120) | INDEX | `""` | 来源名称（如"36氪"） |
| 10 | `source_url` | VARCHAR(800) | INDEX | `""` | 原文链接 |
| 11 | `content_type` | VARCHAR(50) | INDEX | `"article"` | article / video / image |
| 12 | `publish_time` | DATETIME | INDEX | `utcnow` | 发布时间 |
| 13 | `view_count` | INTEGER | — | `0` | 浏览数 |
| 14 | `like_count` | INTEGER | — | `0` | 点赞数 |
| 15 | `favorite_count` | INTEGER | — | `0` | 收藏数 |
| 16 | `comment_count` | INTEGER | — | `0` | 评论数 |
| 17 | `heat_score` | FLOAT | — | `0` | 热度分（公式计算） |
| 18 | `quality_score` | FLOAT | — | `0` | 质量分（0-100） |
| 19 | `sentiment` | VARCHAR(20) | — | `"neutral"` | positive / neutral / negative |
| 20 | `status` | VARCHAR(30) | INDEX | `"published"` | 审核状态 |
| 21 | `audit_comment` | TEXT | — | `""` | 审核意见 |
| 22 | `auditor` | VARCHAR(100) | — | `""` | 审核人用户名 |
| 23 | `audit_time` | DATETIME | NULLABLE | — | 审核时间 |
| 24 | `sensitive_words` | TEXT | — | `""` | 检测到的敏感词，逗号分隔 |
| 25 | `created_at` | DATETIME | — | `utcnow` | 创建时间 |
| 26 | `updated_at` | DATETIME | — | `utcnow` | 更新时间（自动刷新） |

#### 索引

| 索引 | 字段 | 用途 |
|------|------|------|
| PRIMARY | id | 主键 |
| INDEX | title | 标题搜索 |
| INDEX | category | 按分类筛选 |
| INDEX | source_name | 按来源筛选 |
| INDEX | source_url | 采集去重（按 URL） |
| INDEX | content_type | 按类型筛选 |
| INDEX | publish_time | 按发布时间排序/筛选 |
| INDEX | status | 按审核状态筛选 |

#### 内容状态枚举

| 值 | 说明 | 触发条件 |
|----|------|----------|
| `draft` | 草稿 | 创建时默认；审核拒绝后可重新编辑 |
| `pending` | 待审核 | 手动提交；或检测到敏感词自动触发 |
| `published` | 已发布 | 审核通过；仅此状态对普通用户可见 |
| `rejected` | 已拒绝 | 审核员拒绝，附带审核意见 |
| `offline` | 已下架 | 管理员下架已发布内容 |

#### 热度分计算公式

```
heat_score = view_count × 0.4 + like_count × 2 + favorite_count × 3 + comment_count × 2.5
```

每当 `user_behaviors` 表有新增行为记录时，对应内容的 `heat_score` 实时重算。

### 2.3 user_behaviors — 用户行为表

记录用户与内容的每次交互，是用户画像更新和推荐算法的数据源。

#### 字段定义

| # | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | `id` | INTEGER | PK, INDEX | AUTO | 行为记录唯一标识 |
| 2 | `user_id` | INTEGER | FK→users.id, NOT NULL, INDEX | — | 操作用户 |
| 3 | `content_id` | INTEGER | FK→contents.id, NOT NULL, INDEX | — | 被操作内容 |
| 4 | `action_type` | VARCHAR(30) | NOT NULL, INDEX | — | 行为类型 |
| 5 | `duration` | INTEGER | — | `0` | 停留时长（秒），仅对 view 类型有效 |
| 6 | `created_at` | DATETIME | INDEX | `utcnow` | 行为发生时间 |

#### 索引

| 索引 | 字段 | 用途 |
|------|------|------|
| PRIMARY | id | 主键 |
| FOREIGN KEY | user_id → users.id | 用户关联 |
| FOREIGN KEY | content_id → contents.id | 内容关联 |
| INDEX | user_id | 查询某用户全部行为 |
| INDEX | content_id | 查询某内容的互动用户 |
| INDEX | action_type | 按行为类型筛选 |
| INDEX | created_at | 按时间范围查询 |

#### 行为类型枚举

| 值 | 说明 | 对内容的联动 | 对画像的联动 |
|----|------|-------------|-------------|
| `view` | 浏览 | view_count +1 → 热度/质量重算 | 标签权重 +1（+ 浏览时长加成） |
| `like` | 点赞 | like_count +1 → 热度/质量重算 | 标签权重 +5 |
| `favorite` | 收藏 | favorite_count +1 → 热度/质量重算 | 标签权重 +6 |
| `comment` | 评论 | comment_count +1 → 热度/质量重算 | 标签权重 +4 |
| `share` | 分享 | 无计数更新 | 标签权重 +4 |
| `dislike` | 不感兴趣 | 无计数更新 | 标签权重 -6，加入负向标签 |

**浏览时长加成:** 对 `view` 类型，额外加分 = `min(duration / 120, 2)`，阅读超过 4 分钟可获满额 +2。

#### 删除联动

删除用户时，连级删除该用户的所有行为记录：
```sql
DELETE FROM user_behaviors WHERE user_id = :user_id
```

删除内容时，连级删除该内容的所有行为记录：
```sql
DELETE FROM user_behaviors WHERE content_id = :content_id
```

### 2.5 tags — 标签表

内容标签字典，记录每个标签被引用的次数。

#### 字段定义

| # | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | `id` | INTEGER | PK, INDEX | AUTO | 标签唯一标识 |
| 2 | `name` | VARCHAR(80) | NOT NULL, UNIQUE, INDEX | — | 标签名称 |
| 3 | `count` | INTEGER | — | `0` | 引用计数（被多少内容使用） |
| 4 | `created_at` | DATETIME | — | `utcnow` | 创建时间 |

#### 索引

| 索引 | 字段 | 用途 |
|------|------|------|
| PRIMARY | id | 主键 |
| UNIQUE + INDEX | name | 标签名唯一，快速查找和去重 |

#### 使用说明

- 标签存储在 `contents.tags` 字段中（逗号分隔文本），`tags` 表作为字典维护
- `count` 字段需在内容增删时手动维护引用计数
- 前端标签选择器从 `tags` 表读取候选列表，按 `count` 降序排列

### 2.6 recommendation_logs — 推荐日志表

记录每次推荐请求的曝光和用户点击行为，用于推荐效果分析。

#### 字段定义

| # | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|---|--------|------|------|--------|------|
| 1 | `id` | INTEGER | PK, INDEX | AUTO | 日志唯一标识 |
| 2 | `user_id` | INTEGER | FK→users.id, NULLABLE, INDEX | — | 接收推荐的用户（可为空） |
| 3 | `content_id` | INTEGER | FK→contents.id, NOT NULL, INDEX | — | 被推荐的内容 |
| 4 | `scene` | VARCHAR(50) | INDEX | `"mixed"` | hot / personalized / mixed / similar |
| 5 | `action` | VARCHAR(30) | INDEX | `"exposure"` | exposure（曝光）/ click（点击） |
| 6 | `recommend_score` | FLOAT | — | `0` | 推荐评分（0-100） |
| 7 | `reason` | TEXT | — | `""` | 推荐理由文本 |
| 8 | `created_at` | DATETIME | INDEX | `utcnow` | 记录时间 |

#### 索引

| 索引 | 字段 | 用途 |
|------|------|------|
| PRIMARY | id | 主键 |
| FOREIGN KEY | user_id → users.id | 用户关联（可为空，支持匿名推荐） |
| FOREIGN KEY | content_id → contents.id | 内容关联 |
| INDEX | user_id | 查询某用户的推荐历史 |
| INDEX | content_id | 查询某内容的推荐记录 |
| INDEX | scene | 按推荐场景统计 |
| INDEX | action | 区分曝光 vs 点击 |
| INDEX | created_at | 按时间范围统计 |

#### 场景枚举

| 值 | 说明 |
|----|------|
| `hot` | 热门推荐 |
| `personalized` | 个性化推荐 |
| `mixed` | 混合推荐 |
| `similar` | 相似内容推荐 |

#### 推荐效果分析

CTR 计算公式（在 service 层实现）：

```
CTR = count(action='click') / count(action='exposure') × 100%
```

按场景维度可分别统计各推荐策略的 CTR 表现。

#### 删除联动

删除用户/内容时，连级删除相关推荐日志：
```sql
DELETE FROM recommendation_logs WHERE user_id = :user_id
DELETE FROM recommendation_logs WHERE content_id = :content_id
```

## 三、表关系与约束

### 3.1 外键关系

| 子表 | 字段 | 父表 | 父字段 | 级联策略 |
|------|------|------|--------|----------|
| `user_behaviors` | `user_id` | `users` | `id` | 应用层级联删除 |
| `user_behaviors` | `content_id` | `contents` | `id` | 应用层级联删除 |
| `recommendation_logs` | `user_id` | `users` | `id` | 允许 NULL，应用层级联删除 |
| `recommendation_logs` | `content_id` | `contents` | `id` | 应用层级联删除 |

> **说明:** SQLite 默认不强制执行外键约束（需 `PRAGMA foreign_keys = ON`），该系统在应用层（Service 层）通过显式 DELETE 语句处理级联删除。

### 3.2 UNIQUE 约束

| 表 | 字段 | 违反时处理 |
|----|------|-----------|
| `users` | `username` | 返回 400 "用户名已存在" |
| `categories` | `name` | IntegrityError 回滚 |
| `tags` | `name` | IntegrityError 回滚 |

### 3.3 NOT NULL 约束

| 表 | 字段 |
|----|------|
| `users` | username |
| `contents` | title, content |
| `user_behaviors` | user_id, content_id, action_type |
| `recommendation_logs` | content_id |
| `categories` | name |
| `tags` | name |

### 4.1 索引清单

| 表 | 索引字段 | 类型 | 命中场景 |

### 4.2 高频查询与索引匹配

| 查询场景 | SQL 片段 | 命中索引 |
|----------|----------|----------|
| 用户登录 | `WHERE username = ?` | users.username (UNIQUE) |
| 用户列表（按角色） | `WHERE role = ?` | users.role |
| 内容列表（按分类+状态） | `WHERE category = ? AND status = ?` | contents.category + contents.status |
| 推荐候选池 | `WHERE status = 'published' ORDER BY publish_time DESC` | contents.status + contents.publish_time |
| 用户行为聚合 | `WHERE user_id = ?` | user_behaviors.user_id |
| CTR 统计 | `WHERE scene = ? AND action = ? AND created_at BETWEEN ?` | recommendation_logs(scene, action, created_at) |
| 采集去重 | `WHERE source_url = ?` | contents.source_url |
| 审计日志查询 | `WHERE module = ? AND created_at BETWEEN ?` | operation_logs(module, created_at) |

## 五、开发操作说明

### 5.1 数据库初始化

```powershell
cd backend
.\.venv\Scripts\python scripts/init_db.py
```

该脚本会：
1. 删除旧数据库文件（如有）
2. 执行 `Base.metadata.create_all()` 建表
3. 插入演示数据：5 个用户、30+ 条内容、100+ 条行为、8 个分类、30+ 个标签
4. 输出 `smart_media.db` 到 `backend/data/`

### 5.2 应用启动自动建表

`main.py` 中注册了 startup 事件，每次应用启动时如数据库文件不存在会自动建表：

```python
@app.on_event("startup")
def on_startup():
    Base.metadata.create_all(bind=engine)
    ensure_sqlite_schema()
```

### 5.3 迁移到 MySQL/PostgreSQL

修改 `backend/app/core/config.py` 中的 `DATABASE_URL` 环境变量：

```python
# SQLite（当前）
DATABASE_URL = "sqlite:///backend/data/smart_media.db"

# MySQL
DATABASE_URL = "mysql+pymysql://user:password@localhost:3306/smart_media"

# PostgreSQL
DATABASE_URL = "postgresql://user:password@localhost:5432/smart_media"
```

无需修改任何 Model 代码。SQLAlchemy 自动适配不同数据库方言。
